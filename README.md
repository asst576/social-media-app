# Commonplace

A small server-rendered social app for a student project. It uses Python 3.12, Django 5.2, Django Templates, SQLite, built-in authentication, and Pillow.

## Local Setup

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python manage.py migrate
python manage.py createsuperuser
python manage.py runserver 0.0.0.0:5001
```

Open the local CodeRange preview on port `5001`. The SQLite database is `db.sqlite3`; uploaded files are stored under `media/` during local development. Both are ignored by Git.

The local development settings default to `DJANGO_DEBUG=1` and allow `localhost`/`127.0.0.1`. If no `DJANGO_SECRET_KEY` is supplied in debug mode, the process generates a temporary key, so sessions will not survive a server restart. Configure `DJANGO_SECRET_KEY`, `DJANGO_DEBUG`, and comma-separated `DJANGO_ALLOWED_HOSTS` environment variables for the runtime. Non-debug mode requires an explicit secret. Do not use debug mode for a public deployment.

## Accounts and Roles

Visitors can register as regular members, log in, edit their display name/biography, create posts, browse the paginated member directory, follow/unfollow members, and view the chronological feed. The home feed, directory, and profiles require authentication. Profiles and posts are otherwise visible to authenticated users; private accounts are not implemented.

Campaign managers are not self-selected at signup. A trusted staff user signs into `/admin/`, creates or edits a user, and assigns the **Campaign manager** role. Staff access is separately controlled by Django's `is_staff`/superuser permissions.

## Posting and Feed

Posts may contain text, one image, or both. Uploads must decode as JPEG, PNG, or WebP, be no larger than 5 MiB, and stay below the configured pixel limit. Image paths are generated by the application. Reposts are new timeline entries that reference original posts and do not copy their content; the MVP permits one repost per member/post and prevents self-reposts and repost chains.

The feed is newest-first and contains the signed-in member's posts plus posts/reposts from accounts they follow. It is paginated at ten organic entries. Likes, comments, direct messages, notifications, search, hashtags, private accounts, and ranked feeds are out of scope.

## Advertisement Demo

Campaign managers create a draft campaign with ad text, one optional image, a USD budget, and a start/end date. They submit drafts for review. A staff user approves or rejects pending campaigns from the campaign list in Django admin using the available actions.

After approval, the manager can choose **Simulate purchase**. This only records a demo-paid state and the entered amount. No payment provider is called, no card or bank details are accepted, and no money moves. The budget is not consumed by impressions.

An ad is eligible only when it is approved, simulated-paid, and within its scheduled time window. Eligible campaigns are inserted separately from user posts after every five organic feed entries and are visibly labeled **Sponsored**. Staff can pause/resume approved campaigns. The MVP has no behavioral targeting or advanced analytics.

## Validation

Run the automated test suite and Django checks with:

```bash
python manage.py test
python manage.py check
python manage.py makemigrations --check --dry-run
```

The tests use generated images and temporary media directories. For a deployment with `DJANGO_DEBUG=0`, configure persistent media storage and serving with the platform; the development URL configuration only serves uploaded media while debug mode is enabled.

## Deferred

Real payments, likes/comments, messaging, notifications, search/hashtags, private accounts, algorithmic ranking, behavioral ad targeting, and advanced ad analytics are not implemented.
